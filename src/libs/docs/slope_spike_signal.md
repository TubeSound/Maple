# slope_spike 信号生成仕様

## 1. 目的

USDJPYの1分足から移動平均線の傾きを計算し、急激な値動き、下位足の
エントリー方向、エントリー用トレンド中の揺り戻し、短時間に集中する
スパイクを検出する。

主な用途は次のとおり。

- `MA_quick_slope` の大きな負方向スパイクによる投げ売り・暴落候補の検出
- `MA_fast_slope` による下位足エントリー用の短期トレンド判定
- 下位足下降トレンド中の戻り売り候補、上昇トレンド中の押し目候補の抽出
- 同方向スパイクの集中によるバースト検出

MA・傾き計算と信号生成は `libs/slope_spike.py`、可視化は
`strategy/mars/visualize.py` にある。時系列演算はNumPyで行い、データは
`dict[str, np.ndarray]` として扱う。MA期間と回帰期間は信号の定義であるため、
`SlopeSpikeParam` で一元管理する。

## 2. 入力データと傾き

データは `DataLoader.load_data_numpy()` でHistDataのUSDJPY/M1を読み込む。
時刻はJST、価格系列は `float64` のNumPy配列である。

移動平均の標準期間は以下のとおり。

| 系列 | SMA期間 | 用途 |
|---|---:|---|
| Quick | 5 | 急激な値動きとピークの検出 |
| Fast | 18 | 下位足でエントリー方向を決める短期トレンド判定 |
| Middle | 48 | 揺り戻しピークの位置判定 |
| Slow | 240 | 長期的な価格位置の表示 |

各MAの傾きは、直近6点を一次回帰して求める。1分足では回帰係数を
1時間当たりの価格変化率へ正規化する。

```text
slope[%/hour]
  = slope_per_bar * 100
    / ((timeframe_minutes / 60) * abs(window_mean_price))
```

したがって `MA_quick_slope = -2.0` は、現在の短期的な傾きが
年率などではなく、1時間換算で約 `-2%/hour` であることを表す。

Quick slopeの振幅変化を平滑化するため、二乗平均平方根（RMS）を計算する。

```text
quick_slope_energy
  = sqrt(SMA(MA_quick_slope², quick_energy_window))
```

符号付きSlopeの単純移動平均では正負が相殺されるため、二乗してから平均する。
`quick_slope_energy` が高い間は短期的な価格変動が活発であり、低下して
低水準へ落ち着いた状態を、一旦のトレンド終了候補として観察する。

## 3. パラメータ

`SlopeSpikeParam` のソースコード上のデフォルト値は以下のとおり。

| パラメータ | デフォルト | 内容 |
|---|---:|---|
| `quick_window` | 5 | Quick SMAの期間 |
| `quick_energy_window` | 240 | Quick slope energyのRMS期間（本数） |
| `fast_window` | 18 | Fast SMAの期間 |
| `middle_window` | 48 | Middle SMAの期間 |
| `slow_window` | 240 | Slow SMAの期間 |
| `slope_window` | 6 | MA傾きを求める一次回帰期間 |
| `threshold` | 4.0 | 正負スパイク候補を判定する絶対閾値 |
| `dead_zone` | 0.5 | 下位足エントリー用トレンドの不感帯 |
| `pivot_window` | 5 | ピボットの左右に必要な本数 |
| `burst_window_minutes` | 30 | バースト集計時間 |
| `burst_min_spikes` | 3 | バースト成立に必要な同方向ピーク数 |
| `max_gap_minutes` | 5.0 | 連続データとみなす最大時刻間隔 |

検証用チャートでは、例として `threshold=1.5`、`dead_zone=0.1` が使われて
いる。暴落確率の統計では、リアルタイム条件として
`MA_quick_slope <= -2.0` を使用した。

## 4. スパイク候補

スパイクメトリックは移動平均や動的閾値ではなく、
`MA_quick_slope` の値そのものである。

```text
positive_candidate = MA_quick_slope >= threshold
negative_candidate = MA_quick_slope <= -threshold
spike_magnitude     = abs(MA_quick_slope)
```

正負で同じ絶対閾値を使用する。

候補は閾値へ到達した時点で判定できるため、リアルタイム信号として利用できる。
特に暴落の早期検知では、ピボット確定を待たず
`MA_quick_slope <= -2.0` へ初めて到達した時点を監視する。

## 5. ピボットピーク

候補の中から、左右 `pivot_window` 本と比較して厳密な最大値または最小値を
ピークとして抽出する。標準の `pivot_window=5` では合計11本を比較する。

```text
positive_peak:
  positive_candidate かつ
  中心値 > 左右5本すべての値

negative_peak:
  negative_candidate かつ
  中心値 < 左右5本すべての値
```

時系列内に `max_gap_minutes` を超える欠損がある場合、その範囲ではピークを
生成しない。

### リアルタイム利用時の注意

ピボットは右側の5本を必要とするため、M1ではピーク発生から5分後に確定する。
ピーク発生時点で分かっていたものとして売買すると先読みになる。

- 閾値到達: 即時検知可能
- ピボットピーク: 5本後に確定

チャート上ではピークが実際の極値時刻に描画されるが、売買信号時刻は
確定時刻へ5本ずらす必要がある。

## 6. 下位足エントリー用トレンド判定

ここでいうトレンドは、相場全体の大局的なトレンドではない。
M1などの下位足でエントリー方向を決めるための短期トレンドである。
上位足の環境認識や長期トレンドとは分けて扱う。

下位足エントリー用トレンドの方向は、`MA_fast_slope` と `dead_zone` で
判定する。

```text
MA_fast_slope >  dead_zone: 上昇トレンド（+1）
MA_fast_slope < -dead_zone: 下降トレンド（-1）
上記以外:                  中立（0）
```

可視化では下位足の上昇トレンドを青、下降トレンドを赤の背景で表示する。
この背景色はエントリー方向の判定用であり、上位足トレンドを表すものではない。

スパイクの方向と下位足トレンド方向が一致する場合は `trend_peak` とする。

```text
上昇トレンド + positive_peak = 上昇方向のトレンドスパイク
下降トレンド + negative_peak = 下降方向のトレンドスパイク
```

不感帯内で発生したスパイクは `neutral_peak` とする。

## 7. 揺り戻しピーク

揺り戻しはスパイク閾値とは独立して検出する。Quick線とMiddle線の位置関係を
候補条件とし、Quick線に対して同じピボット計算を行う。

### 下位足の下降トレンド

```text
MA_fast_slope < -dead_zone
かつ MA_quick_slope > MA_middle_slope
かつ MA_quick_slope がピボット高値
```

これは下位足の下降トレンド中にQuick線が青線（Middle線）の上へ出た局面で
あり、戻り売りのエントリ候補となる。

### 下位足の上昇トレンド

```text
MA_fast_slope > dead_zone
かつ MA_quick_slope < MA_middle_slope
かつ MA_quick_slope がピボット安値
```

これは下位足の上昇トレンド中の押し目候補となる。

揺り戻しも右側の `pivot_window` 本を使うため、標準設定では5分後に確定する。

## 8. バースト

正方向ピークと負方向ピークは別々に集計する。
直近 `burst_window_minutes` 分に、同方向ピークが
`burst_min_spikes` 個以上あればバースト状態とする。

標準設定では「30分以内に同方向ピークが3個以上」である。
`max_gap_minutes` を超えるデータ欠損があれば、それ以前のピーク履歴を破棄する。

主な出力は以下のとおり。

| 出力 | 内容 |
|---|---|
| `positive_recent_spike_count` | 集計窓内の正ピーク数 |
| `negative_recent_spike_count` | 集計窓内の負ピーク数 |
| `positive_burst` | 正方向バースト状態 |
| `negative_burst` | 負方向バースト状態 |
| `burst_start` | バースト状態へ入った最初の足 |
| `burst_spike` | バースト中に発生したピーク |

## 9. 暴落シグナルの統計評価

HistDataのUSDJPY/M1、2024年1月から2026年6月までを対象に、
`MA_quick_slope` が初めて `-2.0%/hour` 以下になった時点を集計した。
同一局面の重複を避けるため、その後60分間は新しいイベントとして数えない。
イベント数は262件だった。

下表は、シグナル確定時の終値から将来安値までの追加下落確率である。

| 追加下落率 | 15分以内 | 30分以内 | 1時間以内 | 3時間以内 |
|---|---:|---:|---:|---:|
| 0.1%以上 | 45.0% | 56.1% | 64.9% | 73.7% |
| 0.2%以上 | 21.8% | 31.7% | 41.6% | 55.7% |
| 0.3%以上 | 9.5% | 14.9% | 23.7% | 39.3% |
| 0.5%以上 | 1.9% | 4.6% | 10.3% | 17.9% |
| 1.0%以上 | 0.8% | 1.9% | 4.2% | 5.3% |

「1時間以内にさらに0.2%以上下落」を暴落と定義した場合は次のとおり。

- 条件付き暴落確率: 41.6%
- フェイク率: 58.4%
- 通常時の暴落確率: 8.3%
- 通常時に対する発生倍率: 約5倍

`MA_quick_slope <= -2.0` は暴落確率を大きく引き上げるが、単独では
フェイクが過半数ある。そのため、即時警戒信号として使い、Fast/Middleの状態、
負スパイクの反復、価格下落率などを追加条件として評価するのが妥当である。

## 10. 下位足下降トレンドの継続時間

同じ262イベントについて、`dead_zone=0.1` で
`MA_fast_slope` の下降状態を集計した。

| 定義 | 25%点 | 中央値 | 75%点 | 90%点 |
|---|---:|---:|---:|---:|
| `MA_fast_slope < -0.1` の連続時間 | 17分 | 19分 | 25分 | 37分 |
| `MA_fast_slope > +0.1` へ反転するまで | 19分 | 22分 | 42分 | 61分 |

典型的な下降局面は20〜40分程度であり、長いケースでは1時間以上続く。

## 11. 現時点の信号生成案

暴落検知と戻り売りを分けて扱う。

### 暴落警戒

1. `MA_quick_slope` が上側から `-2.0` 以下へ到達したら即時警戒
2. 直近60分の同一イベントを重複除外
3. `MA_fast_slope < -dead_zone` なら下位足の下降トレンドを確認
4. 負ピーク数、負方向バースト、Middle slopeを追加情報として記録

### 戻り売り候補

1. `MA_fast_slope < -dead_zone` の下位足下降トレンド
2. `MA_quick_slope > MA_middle_slope`
3. Quick slopeのピボット高値を5本後に確定
4. ピボット発生時刻ではなく、確定時刻を売買判定時刻にする

## 12. 今後の検証項目

- フェイクを減らすためのFast/Middle slope条件の組み合わせ
- 30分以内の負ピーク数と将来下落率の関係
- 初回 `-2.0` 到達時の価格下落率、ATR、実体幅による条件付け
- アジア・欧州・米国時間帯別の発生確率
- 指標発表時刻や流動性低下時間帯の分離
- ピボット確定遅延を含めた戻り売りの損益評価
- 学習期間と検証期間を分けたアウト・オブ・サンプル確認
